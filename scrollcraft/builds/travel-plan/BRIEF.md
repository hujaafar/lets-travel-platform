# Travel Plan design brief
Adapted to the user's requested admin application, not a marketing landing page.

Evidence: the user asks for a professional Java Travel Management System and explicitly requests Scroll Craft. No visual references or photography were supplied. The attached terminal image only identifies an empty repository.

Authored assumptions, pending the optional visual preference question: calm, capable, editorial travel. Green and warm white. Operational navigation first, overview second, itinerary detail as the focal interaction. No cinematic scroll, autoplay, generated footage, or artificial scroll distance.

The eight brief topics: professional and calm; overview → plans → itinerary → edit; calm overview with focused itinerary detail; confidence through visible data and control; a destination ribbon reveals the exact stay, activities and transport of each stop; premium minimal workspace; separate application screens; no supplied brand assets. These are implementation assumptions, not user quotations or an interview transcript.

Grammar: Live surface. The other seven grammars describe marketing or narrative pages; this task requires a working admin tool. Sample itineraries are explicitly labelled and all counts derive from persisted data. The dashboard functionality takes precedence over the skill's prescribed four scroll device families.

Feeling curve: orientation (sidebar and clear totals), anticipation (next destination photograph), understanding (stop-by-stop itinerary ribbon), confidence (validated editor and confirmed save). Peak: selecting each stop reveals exactly how the journey fits together. The site where I can trace a journey and inspect the details of every destination.

Score: native page flow for overview; hover scale for destination photographs; tab selection and compact fade for the route ribbon; focus and press feedback in the editor. No authored blank scroll. The actual form is the final input. Motion respects reduced-motion preferences.

Fingerprint gate: initial registry was empty. No prior local rows to compare. No generated media. Photographic assets are stored locally for consistent loading. Video/ffmpeg workflow does not apply to this admin application.
